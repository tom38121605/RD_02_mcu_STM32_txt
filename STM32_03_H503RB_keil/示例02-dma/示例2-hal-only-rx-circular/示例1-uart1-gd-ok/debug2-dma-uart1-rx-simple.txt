说明1：原来循环模式和非循环模式的区别，就是dma完成后，是否把两边buf的指针移到起始位的区别，并且循环模式自动启动dma的下一次传输。而非循环模式需手动启动dma的下一次传输。

说明2：半完成中断，是在自动循环模式时（circular mode），为了避免自动循环时回滚覆盖已接收的数据

说明3：对于 DMA 传输 9 个字节的情况，通常传输 4 个字节时会触发半完成中断。        （具体需根据不同单片机和使用情况验证）

说明4： 其实设置dma的源地址 / 目标地址后，就已经决定了谁用哪个dma通道了。 如果从寄存器操作的角度看，__HAL_LINKDMA() 其实就是一个沉余没用的函数

---------------- dma ch0 init  ---（同hal tx）------------------


--- MX_GPDMA1_Init ---  （基本同tx，只是dma通道变了一个）

01. 使能dma1的时钟clock
02. 设置dma1 CH0的优先级为0 (最高)
03. 使能dma1 ch0的irq中断 



--- DMA1 CH0的初始化 ---

10.配置 Node_GPDMA1_Channel0结构体的reg[0],reg[1]值; 设置reg[2],reg[3],reg[4]的初值都为0（数量,源地址,目标地址的实际值以后修改）

11.取得下一个节点Node_GPDMA1_Channel0的地址 （本例的本节点和下一个节点是同一个节点）
   配置 Node_GPDMA1_Channel0结构体的reg[5]。把本节点的地址和其他参数，存到自己的变量reg[5]里 （对应CLLR寄存器）
   Node_GPDMA1_Channel0->LinkRegisters[5] = (Node_GPDMA1_Channel0 & (3fff<<2)) | cllr_mask

12.CCR.2,1 = 1,1， resetdma，暂停dma
   直接对寄存器CCR,CTR1,CTR2,CBR1,CSAR,CDAR,CLLR赋初值，优先级0，快递通道0，数量0，源目地址都0，CLLR为0（寄存器本身）
   CTR2.31-30 =0，每传输完一个包裹就通知  ，CCR.16=0,自动执行整个链表直到最后一个节点                                                                          



---  uart1 初始化  --- 

   21. 使能USART1 clock，使能GPIOC clock，设置uart引脚
   22. uart1的抢占优先级设为0（最高），使能uart1的irq中断 

   23. uart设置CR1, CR2, CR3, 设置数据位8，异步模式，无校验，过采样倍数16，停止位1，无流控，波特率 
   24. CR1.0=1 , 打开uart


--- dma1 ch0 start --- 

   31. 把数据长度，源地址RDR，目标地址aRXBufferUser,  存入到本节点的reg[2],reg[3].reg[4]中

   32. 设置dma的CCR, 使能传输完成中断，传输err中断，更新链接err中断，用户设置err中断，溢出中断，传输半完成中断

   33. 把本节点的高16位地址写入到CLBAR的LBA中 （所有节点的高16位是相同的，而且不需要自动更新 ）    

   34. //把本节点的低16位地址和updatex6写入到CLLR的LA中  （这里的下一个节点是reg5，和本节点是同一个节点，所以会循环执行本节点）
       //允许把该节点的reg[0]-[5]的值自动更新到CTR1，CTR1，CBR1, CSAR, CDAR，CLLR中

   35. 设置CCR.0 = 1，开启dma ch0


--- uart1 start ---

   41. CR3.0=1，使能uart1的err中断； 
   42. CR3.6=1，开启uart1的dma接收
   43. ICR.4=1,清串口空闲中断标志；CR1.4=1,使能串口空闲中断  



---------------- dma ch0 rx 中断处理---------------------


---- GPDMA1_Channel0_IRQHandler ---- HT中断处理 ------

51. dma ch1清HT中断标志CFCR.9
52. 调用半完成中断服务函数 LL_UARTEx_RxEventCallback2，把接收到的10个数据，echo发送到pc串口助手


---- GPDMA1_Channel0_IRQHandler ----TC中断处理 ------

53. dma ch1清TC和HT中断标志CFCR.8 

55. 调用完成中断服务函数LL_UARTEx_RxEventCallback2，把接收到的20个数据，echo发送到pc串口助手

 



---------------- uart1 rx 中断处理---------------------


---- USART1_IRQHandler --- HAL_UART_IRQHandler ----idle中断处理 ------

61. 设置uart，ICR.4=O,  清0串口空闲中断标志
62. 调用完成中断服务函数LL_UARTEx_RxEventCallback2，把接收到的剩余数据，echo发送到pc串口助手 



---------------- dma 循环接收原理---------------------

71. dma的tc完成中断 
72. 自动从CLLR的LBA中，把下一个节点的地址，更新到CLBAR的LBA中，并执行下一个节点  （如果下一个节点和本节点是同一个节点，则循环执行本节点） 
    而CLBAR与循环接收无关，它只保存节点的高16地址（高16位是不变的，无需实际使用）

 NVIC_EncodePriority (  PriorityGroup,   PreemptPriority,  SubPriority)
 
  PriorityGroupTmp =  3;

  //PreemptPriorityBits = ((7  - PriorityGroupTmp) >   4)  ?   4  :  (7  - PriorityGroupTmp);  //__NVIC_PRIO_BITS=4
       PreemptPriorityBits =  7 - 3 =4;     //AIRCR7-4的四位都是抢占优先级 (在这里是IPR[27]的高4位)

  //SubPriorityBits = ((PriorityGroupTmp + __NVIC_PRIO_BITS ) < 7 ) ? 0 : (PriorityGroupTmp - 7 ) + __NVIC_PRIO_BITS;
     SubPriorityBits = (PriorityGroupTmp - 7 ) + __NVIC_PRIO_BITS =0;   //子优先级的位数为0


   //AAA =  (  PreemptPriority &  ( (1 <<  PreemptPriorityBits ) - 1 ) ) << SubPriorityBits

   //BBB =  ((SubPriority  & ((1 << (SubPriorityBits )) - 1 )))
      BBB = 0 & ( 1<<0 - 1 )  = 0 & 0 =0;

  return ( AAA | BBB );  //0

dma_channel_init( )

    
    //CTR1
    //1<<19, 内存地址递增 
    //0<<16, 目标数据都是按字节传输
    //0<<11, 右对齐，不足左边补0
    //0<<3,  外设地址固定
    //0<<0,  源数据都是按字节传输
    //0<<14, 0<<30, 源数据和目标数据都使用默认的端口0
    //0<<26, 目标字节不进行数据交换
    //0<<20, 目标数据每次只搬运1个字节，快递员一次只送一个包裹
    //0<<4,  源数据每次只搬运1个字节，快递员一次只送一个包裹
    //HAL_DMAEx_List_BuildNode(&NodeConfig, &Node_GPDMA1_Channel0);    
       Node_GPDMA1_Channel0.LinkRegisters[0] = 1<<19 | 0<<16 | 0<<11 | 0<<3  | 0<<0 |
                                                     0<<14 | 0<<30 | 0<<26 | 0<<20 | 0<<4; 

    //CTR2                                                 
    //0<<30, 每送完一个包裹，就触发一个事件通知
    //21<<0, 指定DMA搬运的数据源为uart1的RDR   
    // 0<<12,按固定节奏搬完所有包裹（BNDT 指定数量）   //不能提前结束    
       Node_GPDMA1_Channel0.LinkRegisters[1] = 0<<30 | 21<<0 | 0<<12;


    //CBR1, CSAR, CDAR 
       //Node_GPDMA1_Channel0.LinkRegisters[2] = 0;   //nouse    
       //Node_GPDMA1_Channel0.LinkRegisters[3] = 0;   //nouse        
       //Node_GPDMA1_Channel0.LinkRegisters[4] = 0;   //nouse      

    
    //CLLR
       Node_GPDMA1_Channel0.LinkRegisters[5] = ( (uint32_t)(&Node_GPDMA1_Channel0) & (0x3fff<<2) )
                                                      | (1<<31 | 1<<30 | 1<<29 | 1<<28 | 1<<27 | 1<<16);

  
    //init the dma regs x7 （下面是初值，以后会根据需要修改）
    //HAL_DMAEx_List_Init(&handle_GPDMA1_Channel0);    
       GPDMA1_Channel0->CCR |= ( 1<<2 | 1<<1 );         //pause dma, reset dma
       while ((GPDMA1_Channel0->CCR & (1<<0) ) != 0);  //wait dma to close
       
       // CCR.23-22=0,低优先级， 
       // CCR.16=0,自动执行整个链表直到最后一个节点
       // CCR.17=0,指定快递通道：使用默认的通道0
       GPDMA1_Channel0->CCR &= ~(3<<22 | 1<<16 | 1<<17);  

       GPDMA1_Channel0->CTR1 = 0;
       
       //CTR2.31-30 =0, 每传输完一个包裹就通知 
       GPDMA1_Channel0->CTR2 &= ~(3<<30 );
    
       GPDMA1_Channel0->CBR1 = 0;    
       GPDMA1_Channel0->CSAR = 0;    
       GPDMA1_Channel0->CDAR = 0;    
       GPDMA1_Channel0->CLLR = 0;

   if (Size != old_pos)  //first，yes ， 10，0   （必须同时打开tc和ht的中断，才能加这句判断）
    
      //查看索引是单纯的增加，还是发生了回卷
      if (Size > old_pos)                           //yes，索引是单纯的增加
      
         uwNbReceivedChars = Size - old_pos; 
         memcpy( aRXBufferUser2, aRXBufferUser +old_pos, uwNbReceivedChars);         
      
      else                                         //no，索引发生了回卷
      
         //先拷贝当前位置到末尾
         uwNbReceivedChars = RX_BUFFER_SIZE - old_pos;
         memcpy( aRXBufferUser2, aRXBufferUser +old_pos, uwNbReceivedChars);        

         //再拷贝0到Size的位置
         if (Size > 0)

            memcpy( aRXBufferUser2+uwNbReceivedChars, aRXBufferUser, Size );            
            uwNbReceivedChars += Size;



     //把接收到的数据发送到pc串口助手
    iputbytes1(aRXBufferUser2,uwNbReceivedChars);
 
   //标记下一次rxbuf待处理数据的开始位置
   old_pos = Size;   //first，10

HAL_DMA_Abort( *hdma )
 
        uint32_t tickstart =    HAL_GetTick();
    
         //暂停dma
         hdma->Instance->CCR |= DMA_CCR_SUSP;

         hdma->State = HAL_DMA_STATE_SUSPEND;

         //检查是否已经处于暂停状态
         while ((hdma->Instance->CSR & DMA_CSR_SUSPF) == 0)    //等待，直到已经出现暂停状态标志          
  
             if ((HAL_GetTick() - tickstart) > HAL_TIMEOUT_DMA_ABORT)    //如果超时，没有出现暂停标志，则表示已经出错  （一般不会出现这种情况）
              
                  hdma->ErrorCode |= HAL_DMA_ERROR_TIMEOUT; 
                  hdma->State = HAL_DMA_STATE_ERROR;
 
                  if ((hdma->Mode & DMA_LINKEDLIST) == DMA_LINKEDLIST)                 
                      hdma->LinkedListQueue->State = HAL_DMA_QUEUE_STATE_READY;
 
                  __HAL_UNLOCK(hdma);

                  return HAL_ERROR;
             
          
         //reset通道0
         hdma->Instance->CCR |= DMA_CCR_RESET;

         hdma->State = HAL_DMA_STATE_ABORT;

         //CFCR.8,9,10,11,12,13,14=1x7，关闭TC,HT,DTE,ULE,USE,SUSP,TO的中断使能
         __HAL_DMA_CLEAR_FLAG(hdma, (DMA_FLAG_TC | DMA_FLAG_HT | DMA_FLAG_DTE | DMA_FLAG_ULE | DMA_FLAG_USE | DMA_FLAG_SUSP | DMA_FLAG_TO));


         hdma->State = HAL_DMA_STATE_READY;


         if ((hdma->Mode & DMA_LINKEDLIST) == DMA_LINKEDLIST)

             hdma->LinkedListQueue->State = HAL_DMA_QUEUE_STATE_READY;
             hdma->Instance->CBR1 = 0;                                   //清0传输数量


         __HAL_UNLOCK(hdma);
